# 看板：梳理 + 优化与完善方案

> 依据：通读 `renderer/kanban.js`（3150 行）、`main/services/hermes-kanban.js`（1315 行）、`styles.css` 看板段（约 3020–3990 行），并用 Demo 页（mock-bridge）+ headless Chrome 截了 9 张现状图（`/tmp/kb-shots/before-*.png`）。
> 不变的红线：不改 CLI、不写 `~/.hermes`、写端点白名单不扩、token 不出主进程、rail 宽度 400 / 侧栏几何不动、`--blue` 是陶土橙、只用现有 token（没有 `--fill-1/--amber/--line-3`）。

## 一、现状梳理

### 1. 代码结构

| 层 | 文件 | 职责 |
|---|---|---|
| 服务层 | `main/services/hermes-kanban.js` | 读 10 个 GET + 10 个写端点白名单，入参正则校验、字段白名单投影、超时 / 2MB 上限、英文报错翻成中文 |
| 项目 CLI | `main/services/hermes-project-cli.js` | `hermes project` 新建 / 重命名 |
| 渲染层 | `renderer/kanban.js` | 状态 `KB` / `KbDrag`、5 秒轮询（`latest_event_id` 游标）、整页 5 列 / 网格、拖拽（改状态 + 投给 worker）、详情抽屉、派发控制台、新建弹窗、项目弹窗、rail 速览 |
| 样式 | `renderer/styles.css` 3020–3990 | 页头、chip、工具栏、dock、卡片、列、抽屉、派发台、弹窗 |
| 测试 | `test-contracts.js`（看板相关断言很多）、`test-ui.js` S1–S6 / S12 / S13 | — |

`kanban.js` 内部按功能大致分为：
```
1-330     常量 / 状态 / 轮询 / 加载 / ⋯ 菜单
330-930   筛选下拉、受让人、dock、拖拽（指针事件）、落地写
930-1230  卡片 HTML、归组、页头、chip、主体渲染
1230-1410 rail 速览
1410-2050 详情抽屉（编辑 / 日志 / 拆解 / 补规格 / 估算 / 评论 / 改派 / 删除）
2050-2280 派发控制台
2280-2910 新建弹窗 + 项目弹窗（5 种模式）
2910-3150 setupKanban 事件绑定
```

### 2. 功能现状（已经很全）
读：看板 / 详情 / 运行记录 / 统计 / 受让人 / 多看板 / 诊断 / 活跃 worker；
写：新建任务 / 看板、删除、提交派发、拖列改状态、拖到 worker 改派并可立即派发、试运行 / 真派发、拆解 / 补规格 / 估算（会计费）、评论、编辑、项目绑定。

### 3. 看截图和代码发现的问题

**视觉（UI）**

| # | 位置 | 问题 |
|---|---|---|
| V1 | 页头 + chip + 工具栏 | 一共三行：分组 chip 一行、「看板 / 受让人 / 租户」带文字标签的筛选又占一行，加上发丝分隔线，首屏被吃掉约 130px；chip 和列头的计数重复出现 |
| V2 | 列 | 列顶 3px 彩色粗边 + 填充底 + 卡片描边，三层框叠在一起显得重；空列只写「暂无任务」，下面是一整片空白 |
| V3 | 卡片 | 右下角的彩色状态点和所在列的颜色重复；脚行把时间、受让人做成灰胶囊再用「·」分隔，信息噪点多；P3 用绿色、语义别扭（P 级配色本该是红 → 橙 → 灰的递减）；标题和摘要的层级差太小 |
| V4 | 运行中卡片 | 左侧 3px 赭色竖条 + 等宽字体秒表 + 细进度条，三种强调同时出现；赭色和「待办」的黄点接近，容易认错 |
| V5 | 抽屉 | 估算 / 补规格 / 拆解 / 提交派发四个按钮**纵向堆叠，每个下面还挂一段说明**，首屏一半都被它们占了；元信息 chip、工作区、所属项目各占一行描边框；遮罩没盖住页头那 40px；底部离窗口边缘还空着约 15px |
| V6 | 派发控制台 | 展开后把整个看板往下推了约 270px，内部两栏高度又被裁掉（活跃 worker 只露出一行半）；「立即派发」按钮颜色太淡，像是禁用 |
| V7 | 新建弹窗 | 字段平铺 7 项 + 一大段说明，主次不分；「起始状态」的说明文字太长 |
| V8 | 网格视图 | 卡片固定约 350px 宽，宽屏下右侧空出一半 |

**功能（完善）**

| # | 缺口 |
|---|---|
| F1 | 列内**没有排序**（只按 CLI 返回顺序），不能按优先级 / 最近更新 / 创建时间排 |
| F2 | 视图、筛选、排序**不持久化**：重开看板就回到默认 |
| F3 | 没有看板级**键盘快捷键**：`N` 新建、`/` 聚焦搜索、`R` 刷新、`←/→` 在卡片间移动、`Enter` 打开详情 |
| F4 | 搜索命中**不高亮**，长描述里搜到的词看不出在哪 |
| F5 | **卡住的任务没有提示**：就绪等了很久、受阻多天的卡和刚建的长得一样 |
| F6 | 列**不能折叠**：「已完成」越积越多时会把横向空间占满 |
| F7 | 抽屉里**不能用键盘切到上一张 / 下一张卡**，看完一张得关掉再点下一张 |
| F8 | 空列不能直接拖进（只有列头这一小块是落点，空列里大片空白没有落点提示） |

## 二、方案（分三期，可单独验收）

### P1 视觉减负（只改 CSS + 少量模板，不动数据流）
1. **页头合并为两行**：第 1 行「看板名 ⌄（下拉，替代工具栏里的看板选择）· 概览 · 模式 chip ······ 搜索框 · 新建 · ⋯ · ↻ · ✕」；第 2 行「分组 chip ··· 受让人 / 租户（去掉文字标签，改成占位词）· 实时同步」。省出约 44px。
2. **列**：去掉 3px 彩色顶边，改成列头左侧 8px 圆点 + 列名 + 计数；列底色用更淡的 `color-mix(--fill-2 60%)`，卡片保留 1px 发丝描边 + 极轻投影，hover 时上浮 1px。
3. **卡片**：
   - 去掉右下角状态点（和列重复）；
   - 脚行改成「受让人头像式首字母圆 + 名字 · 评论数图标 · 子任务 1/3 迷你进度」，时间放到右侧弱化显示；
   - P 级配色统一为 P0/P1 红、P2 陶土橙、P3 赭黄、P4 不显示（减少噪点），rail 同步；
   - 标题 600 / 正文色，摘要降到 `--text-3`，最多两行。
4. **运行中卡片**：去掉左竖条，改成卡片顶部 2px 绿色进度条（复用 `kbRunPct`）+ 右上角「◷ 10:04」小字，超过 85% 预算时转红（逻辑已有）。
5. **抽屉**：
   - 顶部做成「ID · 状态 chip · P 级 · 受让人」一行元信息；
   - 四个动作改为一排**图标按钮组**（估算 / 补规格 / 拆解 / 提交派发），说明文字收进 tooltip 和确认卡里（确认卡里本来就有）；
   - 「工作区 / 所属项目」合进一个键值表；
   - 遮罩铺满整页、抽屉贴满到底边；
   - 「删除任务」挪到抽屉头的 ⋯ 菜单里，避免放在最显眼的位置。
6. **派发控制台**改为右侧滑出的面板（复用抽屉的外壳），不再把看板往下推；「立即派发」用实心红色危险按钮。
7. **新建弹窗**：标题 + 描述 + 一行「状态 · 优先级 · 受让人」三个下拉；目标看板 / 项目 / 租户收进「更多」折叠区；说明文字缩短到一行。
8. **网格视图**：卡片改为 `repeat(auto-fill, minmax(280px, 1fr))` 自适应铺满。
9. 深色主题逐项复查对比度（契约测试里已有双主题断言，补上新增的类）。

### P2 交互完善（渲染层，不新增任何写端点）
1. **排序**（F1）：⋯ 菜单加「排序：默认 / 优先级 / 最近更新 / 创建时间」，只在本地排。
2. **持久化**（F2）：`view / sort / status / assignee / 已折叠的列` 存 `localStorage('kb-prefs')`，按 profile + 看板区分；搜索词不存。
3. **快捷键**（F3）：看板页可见、且焦点不在输入框时生效，并写进快捷键帮助页；不和全局 ⌘ 快捷键冲突。
4. **搜索高亮**（F4）：标题 / 摘要里命中的词用 `<mark>` 包起来（先 `esc` 转义再包，不引入 XSS）。
5. **卡住提示**（F5）：就绪超过 30 分钟、受阻超过 1 天、待验收超过 1 天的卡，在时间旁显示 `已等 2 天` 的琥珀色小标；阈值写成常量。
6. **列折叠**（F6）：点列头的折叠按钮，列收成 44px 竖条（竖排列名 + 计数），收起后仍能作为拖拽落点。
7. **抽屉内切换卡片**（F7）：`↑/↓` 或抽屉头的 ‹ › 切到同列上一张 / 下一张。
8. **整列都是落点**（F8）：拖拽时整列高亮为虚线落点，空列里显示「松手 → 标记受阻」这类动作文案（复用 `KB_STATUS_ACTION`）。

### P3 代码整理（降低后续维护成本）
1. `kanban.js` 内**按段落拆成同目录多个普通 `<script>`**（不改成 ES module，以免和 refactor 分支冲突）：`kanban-core.js`（状态 / 轮询 / 归组）、`kanban-board.js`（卡片 / 列 / 拖拽）、`kanban-drawer.js`、`kanban-dispatch.js`、`kanban-modal.js`；同步更新 `index.html`、打包自检和契约测试的 `srcOf` 锚点。
   > 这一项可选：收益是可维护性，风险是契约测试里大量按文件切片的断言要改。建议 P1/P2 稳定之后再决定做不做。
2. 把 `renderKanbanBody` 里网格 / 列两套重复的空状态模板抽成一个函数。
